\begin{abstract}
We ask how well classical machine learning classifies the clothing images of Fashion-MNIST, what it costs, and why it fails
where it fails. Five classifiers---Logistic Regression, $k$-Nearest Neighbors, Random Forest, Linear SVM and RBF
SVM---plus a majority-class baseline are trained on two representations: raw pixels and Histograms of Oriented Gradients
(HOG). Every decision (hyperparameters, HOG configuration, final model) is taken on a fixed, stratified 6{,}000-image
validation split; the 10{,}000-image test set is touched exactly once per experiment and every access is recorded in an
audit log. The model selected on validation, an RBF SVM on HOG features, reaches 91.08\% test accuracy
(95\% CI 90.51--91.62\%), significantly better than the same SVM on pixels (McNemar $p<10^{-5}$). HOG lifts the linear
models by 4--5 percentage points (pp) but does not help Random Forest or $k$-NN, and the most accurate model predicts roughly
2{,}400$\times$ slower than a Random Forest that is only 3.5\pp{} less accurate. Confusions among four upper-body
garments (T-shirt/top, Pullover, Coat, Shirt) account for 56--66\% of every model's errors, and Shirt is the hardest class
for all ten trained models---exactly as the exploratory analysis predicted before training. These limits of fixed,
handcrafted features motivate the convolutional network of Phase~2.
\end{abstract}

\section{Introduction}
\label{sec:intro}
An online clothing catalog that tags product photos automatically needs a classifier that is accurate, fast and
small. Deep networks are the default answer today, but whether they are \emph{necessary} can only be judged against a
strong and honestly evaluated classical baseline. Many published baselines are neither: hyperparameters are tuned against
the test set, or models are compared after being tuned on different amounts of data. This report builds such a baseline
on Fashion-MNIST~\cite{xiao2017fashion}, a dataset designed as a harder, drop-in replacement for MNIST digits.

We answer four research questions:
\begin{itemize}
  \item \RQ{1}: How accurately can classical ML classify Fashion-MNIST from raw pixels?
  \item \RQ{2}: Do HOG features beat raw pixels, and for which models?
  \item \RQ{3}: Which model offers the best trade-off between accuracy, end-to-end prediction time and model size?
  \item \RQ{4}: Which classes are confused most, and why do handcrafted features fail there?
\end{itemize}

\textbf{Contributions.}
(i)~A reproducible benchmark of 12 experiments with a committed validation split and a test-set audit log;
(ii)~a validation-only selection protocol that also corrects an unfair comparison between models tuned on different
amounts of data;
(iii)~a cost analysis that counts feature-extraction time, not just model time; and
(iv)~an error analysis, including a paired significance test and an agreement analysis between the two best models,
that links model mistakes back to predictions made from the data before any model was trained.

\section{Background}
\label{sec:background}
\textbf{Classifiers.} \emph{Logistic Regression} is a linear model trained with cross-entropy and an L2 penalty whose
strength is set by $C$ (smaller $C$, stronger regularization). \emph{$k$-NN}~\cite{cover1967nearest} stores the training
set and labels an image by its $k$ nearest neighbors. A \emph{Random Forest}~\cite{breiman2001random} averages many
decision trees, each grown on a bootstrap sample with a random feature subset at every split. \emph{Support vector
machines}~\cite{cortes1995support} find a maximum-margin boundary; the linear variant uses LIBLINEAR~\cite{fan2008liblinear}
and the kernel variant uses the RBF kernel
\begin{equation}
  K(\mathbf{x},\mathbf{x}') = \exp\!\left(-\gamma\,\lVert\mathbf{x}-\mathbf{x}'\rVert^2\right)
  \label{eq:rbf}
\end{equation}
to draw non-linear boundaries. Its prediction cost grows with the number of support vectors, since every test point is
compared with each of them.

\textbf{HOG.} Histograms of Oriented Gradients~\cite{dalal2005histograms} describe an image by the directions of its
edges. The image is divided into cells of $c\times c$ pixels; each cell receives a histogram of $o$ gradient-orientation
bins weighted by gradient magnitude, and overlapping blocks of $b\times b$ cells are normalized together, which makes the
descriptor robust to brightness and contrast. For a $28\times28$ image the descriptor length is
\begin{equation}
  d = \left(\tfrac{28}{c}-b+1\right)^{2} b^{2}\, o .
  \label{eq:hogdim}
\end{equation}

\textbf{Leakage and selection bias.} Using test data for any decision makes the reported test score
optimistic~\cite{kaufman2012leakage}. Even with a clean test set, picking the best of many configurations on validation
makes the \emph{winning validation score} optimistic~\cite{cawley2010overfitting}; we therefore report the untouched test
score as the headline number.

\textbf{Software.} All models use scikit-learn~\cite{pedregosa2011scikit}; HOG uses scikit-image~\cite{vanderwalt2014scikit}.

\section{Data and Experimental Protocol}
\label{sec:protocol}

\subsection{Dataset and Integrity Checks}
Fashion-MNIST contains 70{,}000 grayscale $28\times28$ images in 10 balanced classes---T-shirt/top, Trouser, Pullover,
Dress, Coat, Sandal, Shirt, Sneaker, Bag and Ankle boot---split into 60{,}000 training and 10{,}000 test images. The four
official files are downloaded over HTTPS and verified against the published MD5 checksums. Automated checks confirm the
array shapes, labels in $\{0,\dots,9\}$, no missing values, exactly 6{,}000 training and 1{,}000 test images per class,
and no exact duplicate images within or across the training and test sets.

\subsection{Fixed Split}
A stratified validation set of 6{,}000 images (600 per class, seed 42) is carved from the official training set, leaving
54{,}000 training images. The validation indices are committed to the repository (MD5
\texttt{54ff6b78\allowbreak b27109cd\allowbreak fc3ebe72\allowbreak 04040a07}), so every team member uses an identical
split. The official test set is the final, untouched evaluation set (\cref{fig:protocol}).

\subsection{Leakage Controls}
\begin{enumerate}
  \item The test set is read by exactly one function, \texttt{final\_test\_run()}, once per experiment. Each call appends a
        row to \texttt{test\_log.csv}; the final log has exactly 12 rows, one per experiment.
  \item Hyperparameters, HOG settings and the final model are chosen on validation accuracy only.
  \item Feature scaling (\texttt{StandardScaler}) lives inside each scikit-learn \texttt{Pipeline}, so it is fitted only on
        the rows a model is trained on, including within cross-validation folds.
  \item Exploratory analysis uses the 54{,}000-image training split only.
  \item Error analysis and significance tests read the predictions saved at test time; no model predicts on the test
        set again.
\end{enumerate}

\subsection{Procedure per Experiment}
For each model--feature pair we (1)~fit every grid combination on the 54k training split and score it on validation;
(2)~take the combination with the highest validation accuracy; (3)~refit it on all 60{,}000 training and validation images;
and (4)~evaluate it once on test, recording accuracy, macro-F1, per-class precision and recall, the confusion matrix,
training time, model-only prediction time per 1{,}000 images (best of three runs), and model size (bytes of the pickled
model). Test accuracies are reported with Wilson 95\% confidence intervals; with $n=10{,}000$ these are about
$\pm0.6$\pp{} wide for every trained model.

\section{Feature Representations}
\label{sec:features}
\textbf{Pixels.} Each image is flattened to a 784-dimensional vector in $[0,1]$. Flattening discards the 2-D
neighborhood: a garment shifted by two pixels becomes a very different vector.

\textbf{HOG configuration sweep.} We evaluated $3\times2\times2=12$ HOG configurations: orientations $o\in\{6,9,12\}$, cell
size $c\in\{4,7\}$ pixels and block size $b\in\{1,2\}$ cells. Each was scored with a fast proxy---a linear SVM trained by
SGD with hinge loss---fitted on training features and scored on validation (\cref{tab:hog}). Small cells win by 4--8\pp,
block normalization adds 2--3\pp, and more orientation bins help slightly. The selection rule, fixed in advance, was
\emph{highest validation accuracy; within 0.3\pp{} prefer the shorter vector}. The winner ($o=12$, $c=4$, $b=2$,
$d=1{,}728$ by \eqref{eq:hogdim}; 0.8818) beats the 1{,}296-dimensional runner-up (0.8783) by 0.35\pp, so it was kept.
Extraction costs about 0.22\,s per 1{,}000 images.

so it uses no scaler.

\section{Models and Tuning}
\label{sec:models}
\Cref{tab:grids} lists the validation grids and the selected settings. Two practical constraints shaped tuning on an
8\,GB laptop. First, kernel-SVM training scales super-linearly with the number of samples, so the RBF SVM's 9-point grid
was searched on a stratified 10{,}000-image subset (1{,}000 per class), and only the selected setting was refit on the
full data. Second, Linear SVM fits on 54{,}000 images took 105--924\,s, growing sharply with $C$.

\textbf{Making the validation comparison fair.} Because the RBF SVM was tuned on 10{,}000 images, its tuning-time
validation scores (0.8793 pixels, 0.8867 HOG) came from far less training data than every other model's (54{,}000) and
understated it. \emph{Before} choosing the final model, we fixed a correction: refit the \emph{already selected} RBF
settings on the full 54k training split and score them on the same validation set---no new search and no test data.
This gave 0.9082 (pixels) and 0.9157 (HOG). On equal footing, the validation ranking is RBF SVM\,/\,HOG (0.9157)
$>$ RBF SVM\,/\,pixels (0.9082) $>$ Logistic Regression\,/\,HOG (0.8927) $>$ Linear SVM\,/\,HOG (0.8900).

\textbf{Observations.} The best $C$ lies on the grid boundary for Logistic Regression and Linear SVM (0.01, the smallest)
and for the RBF SVM (10, the largest); we did not widen the grids afterwards (\cref{sec:discussion}). The RBF bandwidth
behaves as theory predicts. After standardization, scikit-learn's \texttt{scale} setting equals $1/d$: about 0.0013 for
pixels and 0.00058 for HOG. The selected values sit at this scale, whereas $\gamma=0.01$ is 17$\times$ too narrow for
HOG; the kernel in \eqref{eq:rbf} then treats almost every pair of images as dissimilar, and HOG validation accuracy
collapses to 11--29\%.

\subsection{RQ1: Raw Pixels}
The best pixel model is the RBF SVM at 89.70\%, followed by Random Forest (87.56\%) and $k$-NN (86.11\%); the linear
models reach only 83.78--84.72\%. A single pixel records brightness at one location, so a linear boundary in pixel space
cannot express shape, and models that build non-linear combinations of pixels do markedly better.

\subsection{RQ2: HOG vs.\ Pixels}
HOG helps the linear models most: $+5.20$\pp{} for Linear SVM (83.78\,$\rightarrow$\,88.98\%) and $+4.14$\pp{} for
Logistic Regression (84.72\,$\rightarrow$\,88.86\%), turning both into competitive models. It lifts the RBF SVM by
$+1.38$\pp{} to 91.08\%. It does not help Random Forest ($-0.53$\pp) or $k$-NN ($+0.20$\pp, well inside the CI)
(\cref{fig:rq23}, left). A plausible explanation for the forest is that each split inspects a single feature, and one raw
pixel is more informative on its own than one HOG bin, which describes a single edge direction in one small block; we did
not test this hypothesis directly.

\begin{itemize}
  \item \textbf{Lowest latency above 87\%:} Random Forest on pixels---87.56\% in about 12\,ms per 1{,}000 images, but a
        366\,MB model.
  \item \textbf{Best accuracy per byte:} Linear SVM on HOG---88.98\% from a 181\,KB model, about 2{,}000$\times$ smaller
        than the forest; its 219\,ms per 1{,}000 images is almost entirely HOG extraction.
  \item \textbf{Highest accuracy:} RBF SVM on HOG---91.08\%, but up to 29\,s per 1{,}000 images, roughly 2{,}400$\times$

\end{itemize}
$k$-NN is both slower and less accurate than the Random Forest, so it is dominated and never the right choice here. For
the catalog use case, the Linear SVM on HOG is the most practical classical model; the RBF SVM sets the accuracy bar
for Phase~2.

\subsection{Selected Model, Significance and Stability}
The model selected on validation is the RBF SVM on HOG (0.9157); the test score played no part in this choice. Its
validation lead over the pixel RBF SVM (0.75\pp) is only about twice the standard error of a 6{,}000-image validation
estimate ($\approx$0.36\pp), so on validation alone it is suggestive rather than conclusive. The held-out test set
confirms it: on the paired test predictions, the HOG model is wrong on 377 images the pixel model gets right, and right
on 515 the pixel model gets wrong. A two-sided McNemar test~\cite{mcnemar1947note} with continuity correction gives $\chi^2=21.0$,
$p=4.5\times10^{-6}$ (exact binomial $p=4.3\times10^{-6}$), so the 1.38\pp{} gain is statistically significant.

A stratified 5-fold cross-validation on a 10{,}000-image subset of the training and validation data gives
$0.8775\pm0.0054$ (folds 0.8765, 0.8860, 0.8715, 0.8725, 0.8810). The small spread indicates the selected configuration is
stable across partitions; the lower mean is expected because each fold trains on only 8{,}000 images.

\section{Error Analysis (RQ4)}
\label{sec:errors}
\textbf{Per-class recall.} Shirt is the hardest class for \emph{all ten} trained models, with recall from 50.9\% (Linear
SVM, pixels) to 75.2\% (RBF SVM, HOG), followed by Pullover (73.5--84.9\%) and Coat (76.4--86.3\%). Trouser, Bag, Sandal,
Sneaker and Ankle boot are easy for every model (\cref{fig:errors}, left). This confirms prediction~(a) from \cref{sec:eda}.

\textbf{Dominant confusions.} From the selected model's confusion matrix (1{,}000 test images per class), the five largest
off-diagonal entries are Shirt\,$\rightarrow$\,T-shirt/top (104), T-shirt/top\,$\rightarrow$\,Shirt (91),
Pullover\,$\rightarrow$\,Shirt (66), Pullover\,$\rightarrow$\,Coat (61) and Shirt\,$\rightarrow$\,Coat (59)
(\cref{fig:errors}, right). Across all ten trained models, confusions within \{T-shirt/top, Pullover, Coat, Shirt\} make up
56--66\% of all errors, confirming prediction~(b).

\textbf{Do the two best models fail on the same images?} \Cref{tab:agree} cross-tabulates the saved predictions of the
RBF SVM on HOG and on pixels. HOG fixes 515 images and breaks 377---a net gain of 138, exactly the 1.38\pp{} test gap.
Of the 515 images both models miss, 391 (76\%) receive the \emph{same} wrong label and 397 (77\%) are upper-body garments.
When two models built on very different representations make the same mistake, the image itself is the likely cause,
not the model. This residual error is what a stronger representation must address.

\section{Discussion and Limitations}
\label{sec:discussion}
\begin{itemize}
  \item \textbf{Grid boundaries.} Three models selected a value on the edge of their grid, so wider grids might add a
        little accuracy. We kept the planned grids rather than spend additional test evaluations.
  \item \textbf{Optimistic validation.} Validation accuracy exceeds test accuracy for all ten trained models, by
        0.02--2.05\pp, as expected when the best of several settings is selected on validation~\cite{cawley2010overfitting}.
        The model ranking is unchanged, and we report the untouched test score.
  \item \textbf{RBF tuning on a subset.} The RBF grid was searched on 10k images; settings that are best at 10k may not be
        best at 54k, so the RBF results are, if anything, a lower bound.
  \item \textbf{Timing.} Timings come from two laptops (Apple M3 and M3 Pro) and two Logistic Regression timings are
        excluded; only large gaps ($\ge10\times$) should be read as firm.
  \item \textbf{Cross-validation} used a 10k subset for time reasons, so it measures stability, not final accuracy.
  \item \textbf{Single seed.} Random Forest results come from one seed; seed variance was not measured.
\end{itemize}

\section{Conclusion and Future Work}
\label{sec:conclusion}
A carefully tuned classical pipeline reaches 91.08\% test accuracy on Fashion-MNIST with an RBF SVM on HOG features,
selected without using the test set for any decision, and significantly better than the same model on raw pixels. HOG is
the single largest improvement for linear models but does nothing for trees or nearest neighbors, and the most accurate
model is also by far the slowest; a 181\,KB Linear SVM on HOG is the most practical deployment choice. The remaining errors
concentrate in four upper-body garments whose distinguishing details---collars, buttons, cuffs---occupy only a few pixels
and are poorly captured by fixed edge histograms. Both outcomes were predicted from the data before training.

\textbf{Phase 2.} We will train a small convolutional network~\cite{lecun1998gradient} (2--3 convolutional blocks with
pooling, dropout and early stopping) on the \emph{same} split and score it with the \emph{same} evaluation code, so it
drops directly into \cref{tab:results} and can be compared to the RBF SVM with the same McNemar test. Our hypothesis is
that learned local filters capture these small details and exceed 91.08\%, chiefly by reducing confusions within
\{Shirt, T-shirt/top, Pullover, Coat\}.

\textbf{Reproducibility.} Code, the committed split, all result files, figures and a decision log recording the reason for
every choice are available at \url{https://github.com/rajdeep-2004/fashion-image-classification-benchmark}. A fresh clone
regenerates every reported result from the saved artifacts in under two minutes.
